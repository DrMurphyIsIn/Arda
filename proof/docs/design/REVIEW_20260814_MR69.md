## Concerns (FAIL/CONCERN items)

### CONCERN 1 — "Stage II CLOSED" overstates the depth≥3 discharge (probe rigor, not theorem)
`g34_deep`'s depth≥4 genericity and depth-3 finiteness rest on **sampling + unproven
monotonicity**, and the `interpolation_lemma` that is cited as making the flatness "a theorem"
covers only the **depth-2 star-of-hubs** family (via I1/I2), NOT the depth-3/4 sampling. So the
architecture's "Stage II of R7' is CLOSED" is stronger than what the artifacts establish. The
modules' own language ("final formal sliver," "probe-backed," "margins grow with depth/count") is
the honest statement; the R7_ARCHITECTURE.md/HANDOFF prose should read "reduced to a named G1
sliver," not "CLOSED." Not a defect in the math shown — a claim-vs-artifact gap in the summary.

### CONCERN 2 — amortized-hub intermediate constant DELTA_CHARGE=0.0240 is false in the limit
`amortized_hub_bound.certify_hub_charge` asserts `slack_v + (tax/2)·#NEAR ≥ 0.0240` for *every*
pure hub, verified by 4000 random trials + an equal-profile sweep. Pushing the true minimizing
profile (all children at `T0−EPS−ε`, just BELOW the window so #NEAR=0, m→∞), I get **0.023953 at
m=2000**, and the analytic limit `EPS/(1+T0) = 0.023587 < 0.0240`. The module even *names*
`analytic_boundary ≈ 0.0236` on line 154 while asserting ≥0.0240 — the assert passes only because
the adversarial search never lands on the limiting profile.
- Mitigant: the constant that actually feeds the final bound is `DELTA_AMORT = 0.0235`, and
  0.023587 > 0.0235, so `ledger ≥ 0.0235·#hubs` (⇒ ≤15 hubs) is NOT broken — but the margin to the
  load-bearing constant is ~9e-5, entirely at float rigor.
- Internal contradiction: `slack_ledger_dichotomy.py:44` calls this same result "CONJECTURAL-
  AMORTIZED… named open," while `amortized_hub_bound.py` (and `slack_ledger`'s own
  `dichotomy_budgets`) call it "PROVEN"/"UNCONDITIONAL"/"THEOREM." The two modules disagree.
- Verdict: the *final* hub bound survives on the true infimum, but as written the intermediate
  lemma is unsound and the "unconditional theorem" language is not earned. Fix: prove the
  minimizing-profile inequality symbolically (it's a 1-var limit) and set the constant to the true
  infimum ≈0.02359 (still > 0.0235 with essentially zero slack — so the ≤15-hub conclusion is
  fragile and should be restated with the honest constant).

### CONCERN 3 — wrong C_1 in the rate-identity docstring
`rate_bound_fixed_n.py` lines 9 and 38 state `C_1 = (26/23)/rhoB ~ 0.881`. Correct value is
0.919446 (I recomputed). R7_ARCHITECTURE.md admits this was "wrong arithmetic in prose only" and
